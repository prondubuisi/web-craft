You are implementing a **complete Playwright user-story suite** for Zineverse (`web-craft`). The goal is not more screenshots and not another feature. The goal is: a first-time visitor, a local maker, and a signed-in scene member can walk every real route and every named mechanic without a pageerror, and the suite documents those walks as tests.

Read first, in this order: `README.md`, `sg.md`, `docs/STATUS.md`, `e2e/flows.spec.ts`, `playwright.config.ts`, `src/App.tsx`, `src/lib/widgets.ts`, `src/lib/primer.ts`, `src/components/Chrome.tsx`, `src/components/DropModal.tsx`, `src/components/EditorMeta.tsx`, `src/views/{Landing,Studio,Editor,Preview,Explore,Help,Board,Fest,Cork,Mail,Jam,Profile,Share,NotFound}.tsx`, `src/lib/seed.ts`. Do not invent routes or buttons. Assert the copy and controls that already exist.

## Mission

Replace the current thin smoke file with a **story-shaped Playwright suite** that:

1. Touches **every route** in `src/App.tsx`.
2. Touches **every top-level view, chrome piece, and reader/editor widget** listed below.
3. Covers the **happy path, the empty/offline path, and the locked/error path** for each story that has one.
4. Distinguishes **local studio (no handle)** from **signed-in API** — most scene verbs need the API; the Pages demo must stay honest when it is down.
5. Leaves `npm run test:e2e` green with `npm run dev` on `:5173` (Vite + SQLite API).

Do **not** start a new feature round. Do **not** add `data-testid` unless a locator is genuinely unstable after trying role/text/label. Prefer the helpers and conventions already in `e2e/flows.spec.ts`.

## User stories to implement

Write each as a `test.describe` + named `test(...)` that a human can read. Group by file if you split.

### A. First visit / readable chrome

1. **First-visit primer.** Fresh storage → `/` shows `.primer` “Make an issue” / “Print it. Pass it.” / “Remix the pile”. “Glossary” goes to `/help`. “Got it” dismisses and stays dismissed on reload (`zineverse.primer.v1`).
2. **Collapsed nav.** Topbar is Cover, Studio, Stream, Help, MAIL. No Board / Fest / Desk in `.nav-links`. Brand says `local` or `api live`.
3. **Offline honesty.** If you can force `online === false` (or document a headed check): `.local-note` explains local studio and links Help; Stream has no `.scene-links`. When API is up, LocalNote is absent and SceneLinks show Desk/Board/Fest.
4. **Cover make/print/pass/remix.** “Make an issue” opens `/studio` with the new-issue modal. “Enter the studio” → `/studio` without the modal. Vibe cards switch `data-vibe`. “One finished issue” → read after hours.
5. **Help glossary.** `/help` lists every term in `ENTRIES` (issue, vibe, drop, snapshot, snap, scatter, remix, bag, distro shelf, archive, board, fest, desk, jam, letters, b-side, corpse, handle). CTAs to studio and stream work.
6. **404.** `/no-such-dimension` → “this page tore off”.
7. **Skip link.** `.skip-link` is in the DOM and points at `#main`.

### B. Maker — studio and editor

8. **Create from studio.** Studio → “New issue” → name it → “Open the page” → title input matches.
9. **Slash commands + tray.** Type `/` and insert several widgets; click tray `/sticker`, `/halftone`, `/poll`, `/tape`, `/strip`, `/toc`, `/insert`, `/reply`, `/blackout`, `/colophon`. Cover the rest of `WIDGETS` in the same test or a table-driven loop. Undo (Meta+Z) removes the last insert.
10. **Block tools.** Select a block: move up/down, duplicate, delete, drag handle present. Inspector edits text/word for the selected type.
11. **Editor meta.** Fill tags, series `rooftop hours`, issue `#`, pen name, b-side text, dedication, errata, run-of (edition size). Toggle finish clean → riso → grain (`finish-riso` class). Toggle scatter on/off (`.zine-page.scatter`). Compilation chip appears for a public seed issue and can be toggled.

    - “In a minute” → reader sealed with countdown (do not sleep a full minute; assert lock + copy).
    - Exquisite corpse toggle → after drop, More sheet has “Copy corpse link” for the author.

## Engineering rules

- **One worker, serial.** Shared `localStorage` + one SQLite file. Do not enable full parallel.
- **Fresh storage per test** via the existing `fresh()` init script. Do not leak primer dismissal or claimed handles across tests except inside a multi-step story that says so.
- **No pageerrors.** Keep the afterEach collector. Filter network `Failed to load resource` the same way.
- **Clipboard.** Grant permissions; `test.skip` if the hash is empty — do not fail CI on a Chrome clipboard quirk.
- **Print.** Stub `window.print` so “Print issue” / “Print fold sheet” do not hang. Assert fold markup, not paper.
- **File inputs.** Use `e2e/fixtures/` (tiny PNG, tiny valid `.zine.json`). Never hit a real camera or microphone.
- **API optional.** Every scene story must `test.skip` (with a reason) if Claim studio is disabled or `/health`-equivalent fails. Local-studio stories must still pass with API down.
- **Two users.** For mail, watch, like notices, board swap-as-other: two contexts, two handles. Clean up is “leave the handles”; do not write a delete-user API that does not exist.
- **Locators.** Prefer `getByRole`, `getByLabel`, exact button copy already in the UI (`Stuff in bag`, `More on this issue`, `Drop now`, `Claim studio`). Reuse `clickText` / `clickIncludes`. Avoid brittle nth-of-type except vibe cards if necessary.
- **Timeouts.** Stay within the 45s test / 8s expect budget. Do not `waitForTimeout` for “In a minute” to expire.
- **No new product copy** just to make tests easier, except a `data-testid` as a last resort on the drop toast or MAIL count if roles are insufficient.
