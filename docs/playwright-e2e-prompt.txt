CORRECTION: this draft's "nav links present on every page" framing below
(Chrome / cross-page section, and the viewport-matrix note) is wrong for the
Editor. The Editor has no Topbar by design — its own `.editor-bar` chrome
carries only a "← studio" link back to Studio. Stream and Help are not
persistent-nav destinations reachable from inside the Editor; they're a hop
away, through that back link. The implemented test
(`cover.spec.ts`: "nav chrome is on every top-level route") already gets this
right — it loops `/`, `/studio`, `/help`, `/explore`, `/board`, `/fest`,
`/cork`, `/mail` and correctly does not include `/edit/:id`. Read every "nav
on every route" phrase below as "every Topbar-bearing route," not literally
every route in `App.tsx`.

---

Write a comprehensive Playwright e2e suite for the Zineverse app (this repo) that
exercises every route, every shared component, and every major user story. An
existing spec at e2e/flows.spec.ts already covers some flows — read it first,
match its conventions, and ADD new test files rather than duplicating what's there.

CONVENTIONS TO MATCH (from e2e/flows.spec.ts)
- Use the existing `fresh(page)` helper pattern: clear localStorage once per
  session via addInitScript, and capture pageerror/console-error events into an
  array asserted empty in afterEach. Every new spec file should do the same.
- baseURL is http://127.0.0.1:5173, channel 'chrome', headless, single worker,
  fullyParallel: false (see playwright.config.ts) — don't fight this, write
  tests that are safe to run serially against shared localStorage/SQLite state.
- Prefer role/text-based locators over brittle CSS where possible, but this app
  has stable utility classes worth using directly: .comic-btn, .tray-item.on,
  .zine-card, .zine-wall, .issue-chip, .board-card, [role="dialog"], .drop-toast,
  [data-vibe] (on page root, tells you which vibe theme is active).
- Group specs by area under e2e/, e.g. e2e/editor.spec.ts, e2e/preview.spec.ts,
  e2e/social.spec.ts, e2e/nav-offline.spec.ts, e2e/mobile.spec.ts.

TWO RUN CONDITIONS — TEST BOTH, EXPLICITLY
This app has a local-first / API-optional architecture. Nearly every view
branches on `online` (API reachable) and `session` (user has claimed a handle).
Write each social/data feature as a pair of tests (or a parameterized test)
covering:
  1. API-live + signed-in — full read/write behavior.
  2. API-offline or signed-out — localStorage-only fallback, disabled controls,
     "claim a handle" placeholders, hidden nav clusters.
Concretely: Chrome's <SceneLinks> (Desk/Board/Fest/Letters nav links) render
ONLY when online; <LocalNote> ("Local studio...") renders ONLY when offline —
assert both states rather than just one. Comments/Reviews/Margins textareas are
disabled with a "claim a handle" placeholder when online-but-signed-out.

VIEWPORT MATRIX
Run the Editor flows (its own `.editor-bar` chrome, not the Topbar — Editor
has no Topbar by design) and, separately, the Topbar-bearing views' nav, at
both:
  - desktop: 1440x900 (default) — uses .desktop-only tray/inspector
  - mobile: 390x844 — uses .mobile-only FAB (+) button, .sheet BottomSheet,
    swipe-based FlipReader navigation
Assert .desktop-only elements are hidden on mobile and vice versa, not just that
mobile equivalents exist.

USER STORIES BY SECTION (write at least one test per bullet; group logically)

Landing (/)
- First-time visitor sees the primer ("Make an issue"); dismissing it
  ("Got it") persists via localStorage so a reload doesn't show it again.
- Switching the vibe rail (.vibe-card, 5 vibes) updates [data-vibe] on root and
  the "Build with {vibe}" CTA text.
- "Make an issue" opens /studio with the new-issue modal.
- "Enter the studio" navigates to /studio.
- The sample-issue link only renders when a published sample zine exists —
  test both with and without seeded data.

Studio (/studio)
- Header chip reflects all three states: signed-in (@handle), API-live-but-
  signed-out, and fully offline.
- "New issue" modal: pick a vibe, title it, "Open the page" → Editor.
- Import JSON: valid file loads a zine; invalid JSON triggers the
  window.alert('That file is not a Zineverse issue.') — assert via page.on('dialog').
- Claim-handle modal: register a new handle+password, toggle to "I already have
  one" and log in, sign out. Skip claim tests gracefully if API is offline
  (mirror the existing test's `if (!enabled) test.skip(...)` pattern).
- "Reset demo" only appears when logged out.
- Bag shelf section only renders when the bag is non-empty.

Editor (/edit/:id)
- Nonexistent id shows the "this issue wandered off" fallback with a link back
  to /studio.
- Title edit, vibe select (desktop only), mode toggles (page/phone/tablet/fold).
- Slash-command palette: press "/", filter by typing, Enter inserts the first
  match — cover at least sticker, sfx, quote, poll, blackout, colophon.
- Widget tray (desktop .tray-item) vs mobile FAB → BottomSheet — same widget
  set must be reachable both ways.
- "snap" image upload item (accept=image/*) runs the cutout pipeline; assert
  graceful fallback to raw image if cutout fails (or just assert an image block
  appears — don't over-assert on the cutout internals).
- Block controls: drag handle reorder (or, when zine.scatter is on, free x/y
  placement via onPageDrop), duplicate (+), move up/down, delete (×), mobile-
  only inspect (✎).
- Empty-canvas hint ("type / to drop a sticker...") when blocks.length === 0.
- Keyboard shortcuts: Meta/Ctrl+Z undo, +Shift or Meta/Ctrl+Y redo, Meta/Ctrl+
  Enter opens Drop modal, Escape closes any open panel, Backspace/Delete
  removes a selected block (only when not focused in a text input).
- Inspector (desktop panel / mobile sheet): exercise per-block-type controls
  for at least sticker (rotation slider, cut-out-background), hero (density/
  RGB-split sliders, art-library picker), poll (add/remove option at 2/6
  bounds), sfx (preset word buttons).
- EditorMeta fields: tags, series, issue number, pen name, b-side, dedication,
  errata, edition size, finish toggle (clean/riso/grain), scatter toggle,
  compilation picker (attach other published zines, capped at 8).
- DropModal: visibility toggle (public/unlisted), exquisite-corpse toggle,
  passphrase (min 4 chars), all six schedule buttons (Drop now / In a minute /
  In an hour / Tomorrow / In a year / In a decade), and footer actions (Copy
  studio link, Copy snapshot link, Export JSON) — assert the matching
  .drop-toast text for each drop path.

Preview (/z/:id, plus ?k= and ?chain= query variants)
- Missing/hidden-unlisted-without-key id → "missing issue" fallback.
- Sealed/locked issue (drop not live yet): .next-issue countdown + .drop-lock
  panel; Comments/Reviews must NOT render while locked.
- Passphrase-gated capsule: wrong pass shows inline error, correct pass unlocks
  (cover the offline hint shown when API is unreachable too).
- Exquisite-corpse chain mode (?chain=): last-page-only view, "add the next
  page" textarea, "Pass it on" submit.
- Flip/Scroll toggle switches between FlipReader (swipe/prev-next, page
  counter "PAGE n / total") and normal scroll.
- Action row: Like/Liked toggle updates count; Remix creates a copy and routes
  to its Editor; Stuff-in-bag toggle; Edit link appears only when isMine.
- "More on this issue" reveals .issue-more: Copy snapshot, Preview/Hide fold,
  Stock in distro, Nominate/Nominated (count), Watch this run (only if
  zine.series), Check out/On loan (only if archived & not mine), Claim N/M or
  Out of print (only if editionSize & not mine), Unfold/Fold b-side (only if
  bSide), Copy corpse link (only if mine & chainOpen).
- Margins: per-block ¶ toggle opens note panel; disabled input when
  online-but-signed-out.
- FoldSheet renders below (assert it doesn't crash while its QR code renders
  asynchronously — wait for the svg, don't assert on generation timing).

Explore (/explore)
- Search input filters the stream (assert every visible card matches the query
  the way the existing test does with .poll()).
- Lane filters (all/watching/jam/archive) — watching lane behavior differs
  when signed out.
- Vibe filter, sort (new/likes/remixes), and dynamic tag chips (up to 12) all
  narrow the result set.
- Empty state: "Nothing in this lane yet. Try another vibe."
- "Pull from the pile": online success routes to a random pile issue; offline
  or empty-pile falls back to a local pick or no-ops — test the no-op case
  explicitly with an empty filtered set.
- Live jam banner only renders when a live jam exists.
- Card Remix button creates a copy and routes to Editor; sealed cards show
  "NEXT ISSUE · {countdown}" instead of like/remix counts and route through
  the same sealed/.drop-lock experience as Preview.

Board (/board)
- Kind filter (all/trade/collab/feedback).
- Post form: kind toggle, 280-char textarea, optional "Attach an issue" select
  (only if the user has published zines), Pin it (disabled until non-empty).
- Own-listing controls (swapped/unswap, pull pin) only show for the posting
  handle — test the author-match edge case isn't broken by "@" prefix
  stripping.
- Empty state: "quiet board. pin the first want."
- Offline/signed-out hint text about local-only persistence.

Fest (/fest)
- Scene search filters the table list by substring.
- Setup form: table name, scene, blurb, zine picker (only if the user has
  published zines) → "Set up a table".
- "Sit" toggle at a table, sitters list rendering.
- Empty state: "the floor is empty. set a table first."

Cork (/cork)
- Add-pin form (text input + "Pin it").
- Drag a pin via Pointer events (mouse.down/move/up — this is NOT HTML5 DnD,
  so use page.mouse, not dragTo) and assert its inline left/top/rotate style
  changed.
- "paste" button only renders when the user has a draft/unpublished zine —
  clicking it creates a sticker block and routes to that zine's Editor.
- Unpin (aria-label="Unpin") removes a pin.
- Empty state: "the board is blank. pin something ugly."

Jam (/jam/:id)
- Live vs closed jam chip, prompt/format hint.
- Zine wall filtered to the jam; empty state "Nobody printed into this jam
  yet."
- "Enter the jam" routes to /studio (not directly to Editor — don't assert the
  wrong destination).
- Unknown id with jams available falls back to the first demo jam rather than
  immediately 404ing.

Profile (/u/:handle)
- "mine" detection: session.name === handle, or signed-out + handle === 'you'.
- Follow toggle ("Watch wall"/"Watching") only renders for other users' walls.
- "Write a letter" links to /mail/:handle.
- Bio editor (scene + bio fields, Save/Saved) only for your own signed-in
  wall; read-only bio otherwise.
- Issues grouped by series; sealed issues show "sealed" instead of like count.
- Empty state with a Studio link shown only on your own empty wall.
- Conditional sections — test presence AND absence: Fest table card, On-loan
  badges, Passport stamps, Distro shelf, only when that data exists.
- Guestbook is always visible: sign it via the 200-char textarea.
- Badge row: earned vs .dim unearned badges.

Share (/s#<token>)
- Valid encoded snapshot renders the issue (reuse the existing "copy snapshot
  → paste into /s#hash" pattern from flows.spec.ts as a model).
- Invalid/garbage hash → "broken snapshot" fallback with a link to /explore.
- Sealed snapshot (dropsAt in future) shows .drop-lock with NO unlock
  mechanism (this differs from Preview — don't assume a passphrase form here).
- "Remix into studio" imports the zine and routes to its Editor.

Mail (/mail and /mail/:handle)
- Thread list, unread badge, empty state "no envelopes yet. write first."
- Compose form (to-handle input only shown with no :handle param).
- Sending a letter vs toggling "postcard" mode: assert the vibe-picker row
  appears, the char limit changes (140 vs 400), and the submit label changes
  ("Mail postcard" vs "Send letter"), disabled until both body and destination
  are set.
- Offline hint about local-only persistence.

Help (/help) — static glossary
- All 18 glossary terms render (issue, vibe, drop, snapshot, snap, scatter,
  remix, bag, distro shelf, archive, board, fest, desk, jam, letters, b-side,
  corpse, handle).
- "Open the studio" and "The stream" links route correctly.

NotFound (*)
- Unknown route shows the 404 chip and all three recovery links (Cover,
  Studio, Stream) work.

Chrome / cross-page (Topbar, Inbox)
- Nav links (Cover/Studio/Stream/Help) present on every Topbar-bearing route
  — every top-level screen except the Editor, which has no Topbar by design
  (its `.editor-bar` carries only a "← studio" link; Stream and Help are a
  hop back through Studio from there, not part of a persistent global nav).
  Letters + @handle links appear only when signed in.
- Inbox: "MAIL" toggle opens role="dialog" aria-label="Notices"; unread items
  show .fresh styling and .hot on the toggle button; opening the panel marks
  notices read; empty state "quiet on this frequency."; click-outside closes
  the panel.

Shared block-type coverage (via Editor + Preview together)
For BlockView, write at least one round-trip test per type (insert in Editor,
verify both the editable and read-only rendering in Preview) for: heading,
sticker, hero, grid, divider, sfx, glitch, stack, quote, poll (vote as a
reader and assert bar width / disabled-when-no-onVote), audio (both with and
without a src — assert the "no tape loaded" hint), strip, colophon, blackout
(toggle a word hidden in edit mode, assert ████ redaction in read mode),
contents, reply (submit via ReplyForm when onMail is available; assert the
"claim a handle to mail this back" text when it's the owner's own view),
insert.

CROSS-CUTTING RELIABILITY NOTES — build these into helpers, don't skip them
- Drop-toasts auto-dismiss after 2.4–3.6s; assert their text immediately, not
  after a wait.
- Profile's "Saved" confirmation flashes for ~1.6s — same rule.
- Explore's remote search has a 180ms debounce — use expect.poll (as the
  existing sunday-search test does) instead of a fixed timeout.
- FoldSheet's QR code renders asynchronously via QRCode.toString — wait for
  the svg element to appear rather than asserting instantly.
- "Print issue" / "Print fold sheet" trigger window.print() — don't try to
  assert print output; instead assert the .no-print class / fold-print body
  class toggle as a proxy.
- Wrap any window.alert-triggering action (bad JSON import, failed upload) in
  a page.on('dialog', d => d.accept()) handler so the test doesn't hang.
